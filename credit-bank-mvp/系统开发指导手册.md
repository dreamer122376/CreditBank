# 终身学习学分银行积分管理系统 - 开发指导手册

## 一、数据库表结构说明

### 1. 机构表（organization）

**系统描述：** 存储加盟的院校、企业或培训机构信息，管理机构的入驻审核和状态。

**表结构：**

| 字段名            | 数据类型         | 允许空      | 说明                 |
| -------------- | ------------ | -------- | ------------------ |
| id             | bigint(20)   | 否        | 主键，自增，机构唯一ID       |
| name           | varchar(100) | 否        | 机构全称（如：XX大学继续教育学院） |
| contact_person | varchar(50)  | 是        | 联系人姓名              |
| contact_phone  | varchar(20)  | 是        | 联系电话               |
| address        | varchar(200) | 是        | 机构地址               |
| status         | tinyint(4)   | 是        | 状态：0待审核，1启用，2禁用    |
| created_at     | datetime     | 是        | 创建时间               |
| updated_at     | datetime     | 是        | 最后修改时间             |

**索引：** 主键 id

---

### 2. 系统用户表（sys_user）

**系统描述：** 存储所有身份账号（超管、机构管理员、专家、学生），一个账号对应一个身份角色。

**表结构：**

| 字段名          | 数据类型         | 允许空      | 说明                                |
| ------------ | ------------ | -------- | --------------------------------- |
| id           | bigint(20)   | 否        | 主键，自增，用户ID                        |
| username     | varchar(50)  | 否        | 登录账号（唯一约束，手机号或邮箱）                 |
| password     | varchar(255) | 否        | 加密后的密码                            |
| real_name    | varchar(50)  | 是        | 真实姓名                              |
| phone        | varchar(20)  | 是        | 手机号                               |
| email        | varchar(100) | 是        | 电子邮箱                              |
| role         | varchar(20)  | 否        | 角色：admin/org_admin/expert/student |
| org_id       | bigint(20)   | 是        | 所属机构ID（学生和机构管理员必填）                |
| expert_field | varchar(100) | 是        | 专家擅长领域（仅专家角色使用）                   |
| balance      | int(11)      | 是        | 当前可用总积分（核心资产字段）                   |
| status       | tinyint(4)   | 是        | 账号状态：1正常，0冻结                      |
| created_at   | datetime     | 是        | 注册时间                              |

**索引：**
- 主键 id
- 唯一索引 uk_username (username)
- 普通索引 idx_org_id (org_id)

---

### 3. 积分规则表（credit_rule）

**系统描述：** 配置"做什么事得/扣多少分"的奖惩标准，相当于系统的"印钞规则"。

**表结构：**

| 字段名          | 数据类型         | 允许空      | 说明                       |
| ------------ | ------------ | -------- | ------------------------ |
| id           | bigint(20)   | 否        | 主键，自增，规则ID               |
| event_code   | varchar(50)  | 否        | 事件编码（唯一约束，如 COURSE_DONE） |
| event_name   | varchar(100) | 否        | 事件中文名（如：完成一门课程）          |
| credit_value | int(11)      | 否        | 变动值（正数=加分，负数=扣分）         |
| scope        | varchar(20)  | 是        | 适用对象：ALL/STUDENT/EXPERT  |
| is_enabled   | tinyint(4)   | 是        | 是否启用：1启用，0停用             |
| created_at   | datetime     | 是        | 创建时间                     |

**索引：**
- 主键 id
- 唯一索引 uk_event_code (event_code)

## 二、功能模块实现流程

### 功能1：积分规则管理

**系统描述：** 配置"做什么事得/扣多少分"的奖惩标准，相当于系统的"印钞规则"。

**涉及数据表：** credit_rule

**实现流程：**

1. **列表展示功能**
   - 查询 credit_rule 表所有记录
   - 前端展示：事件编码、事件名称、积分值、适用对象、启用状态
   - 支持按 event_code 或 event_name 搜索

2. **新增积分规则**
   - 管理员填写：event_code、event_name、credit_value、scope、is_enabled
   - 后端校验：event_code 唯一性（利用唯一约束）
   - 插入 credit_rule 表
   - 返回成功提示

3. **编辑积分规则**
   - 根据 id 查询现有规则
   - 管理员修改：event_name、credit_value、scope
   - 注意：event_code 不允许修改（后端代码作为常量调用）
   - 更新 credit_rule 表对应记录

4. **启用/禁用规则**
   - 根据 id 更新 is_enabled 字段（1启用，0停用）
   - 禁用后，该规则在积分发放时不再被触发
   - 前端展示状态切换按钮

5. **删除规则**（可选）
   - 一般建议禁用而非删除（保留历史数据）
   - 如果必须删除，需校验是否已被 transaction_log 引用

**关键代码逻辑：**
```java
// 触发积分规则时的核心逻辑
PointRule rule = creditRuleMapper.selectOne(

if (rule != null) {

}
```

### 功能2：转换规则管理

**系统描述：** 定义"积分可以兑换什么商品/权益"，以及对应的价格和库存。

**涉及数据表：** exchange_rule、sys_user、transaction_log、application

**实现流程：**

1. **列表展示功能**
   - 查询 exchange_rule 表所有记录
   - 前端展示：商品名称、所需积分、库存、每日限兑、启用状态
   - 支持按商品名称搜索

2. **新增兑换规则**
   - 管理员填写：item_name、item_icon、required_credit、stock、daily_limit、is_enabled
   - 插入 exchange_rule 表
   - 返回成功提示

3. **编辑兑换规则**
   - 根据 id 查询现有规则
   - 管理员修改：商品名称、所需积分、库存数量、每日限兑
   - 更新 exchange_rule 表

4. **启用/禁用规则**
   - 根据 id 更新 is_enabled 字段
   - 禁用后，学生端不再显示该兑换项

5. **学生兑换流程**（核心业务）
   - 学生选择商品，提交兑换申请
   - **后端校验逻辑：**
     - 查询 exchange_rule 获取 required_credit 和 stock
     - 查询 sys_user 获取学生当前 balance
     - 校验：balance >= required_credit（积分足够）
     - 校验：stock > 0（库存充足）
     - 校验：每日限兑次数（查询 transaction_log 按日期统计）
   - **兑换操作：**
     - 扣减学生积分：sys_user.balance -= required_credit
     - 扣减库存：exchange_rule.stock -= 1
     - 写入流水：transaction_log（amount=-required_credit, biz_type='EXCHANGE'）
     - 如需审批：插入 application 表（biz_type='EXCHANGE'）
   - 返回兑换成功提示

6. **库存管理**
   - 支持手动补充库存
   - 支持查看库存消耗记录（关联 transaction_log）

**关键代码逻辑：**
```java
// 兑换校验
ExchangeRule rule = exchangeRuleMapper.selectById(ruleId);
SysUser user = sysUserMapper.selectById(userId);

// 积分校验
if (user.getBalance() < rule.getRequiredCredit()) {
    throw new BizException("积分不足");
}

// 库存校验
if (rule.getStock() <= 0) {
    throw new BizException("库存不足");
}

// 每日限兑校验
int todayCount = transactionLogMapper.countByUserAndDate(userId, today);
if (todayCount >= rule.getDailyLimit()) {
    throw new BizException("已达每日兑换上限");
}

// 执行兑换（事务控制）
@Transactional
public void exchange(Long userId, Long ruleId) {
    // 1. 扣减积分
    // 2. 扣减库存
    // 3. 写入流水
}
```

### 功能3：认证标准管理

**系统描述：** 设定"修满多少积分、是否需专家签字"才能获得证书的毕业门槛。

**涉及数据表：** cert_standard、sys_user、application、transaction_log

**实现流程：**

1. **列表展示功能**
   - 查询 cert_standard 表所有记录
   - 前端展示：认证名称、最低积分要求、是否需专家审批、有效期、启用状态

2. **新增认证标准**
   - 管理员填写：standard_name、min_credit、need_expert_approve、validity_days、is_enabled
   - 插入 cert_standard 表

3. **编辑认证标准**
   - 根据 id 查询现有标准
   - 管理员修改相关字段
   - 更新 cert_standard 表

4. **学生申请认证流程**（核心业务）
   - 学生选择认证标准，提交申请
   - **后端校验逻辑：**
     - 查询 cert_standard 获取 min_credit 和 need_expert_approve
     - 查询 sys_user 获取学生当前 balance
     - 校验：balance >= min_credit（积分达标）
   - **申请操作：**
     - 插入 application 表：
       - biz_type = 'CERT_APPLY'
       - biz_key = cert_standard.id
       - applicant_id = 学生ID
       - current_status = 1（待机构审）或 2（待专家审）
   - 返回申请成功提示

5. **审批流程**
   - **机构管理员审批：**
     - 查询 application 表（current_status=1）
     - 审批通过：更新 current_status=2（待专家审）或直接=3（通过）
     - 审批驳回：更新 current_status=4，填写 reject_reason
   - **专家审批：**
     - 查询 application 表（current_status=2）
     - 审批通过：更新 current_status=3
     - 审批驳回：更新 current_status=4
   - **通过后操作：**
     - 计算证书有效期：当前日期 + validity_days
     - 可生成证书编号（建议另建证书表存储）
     - 写入 transaction_log（可选，记录认证通过）

**关键代码逻辑：**
```java
// 认证申请校验
CertStandard standard = certStandardMapper.selectById(standardId);
SysUser user = sysUserMapper.selectById(userId);

if (user.getBalance() < standard.getMinCredit()) {
    throw new BizException("积分未达标，无法申请认证");
}

// 创建申请单
Application app = new Application();
app.setBizType("CERT_APPLY");
app.setBizKey(standardId);
app.setApplicantId(userId);
app.setOrgId(user.getOrgId());

// 根据是否需要专家审批设定初始状态
if (standard.getNeedExpertApprove() == 1) {
    app.setCurrentStatus(1); // 待机构审
} else {
    app.setCurrentStatus(2); // 待专家审（或直接通过）
}

applicationMapper.insert(app);
```

### 功能4：业务流程管理

**系统描述：** 配置"一个申请单需要经过几级审批"，简化配置但不做拖拽流程图。

**涉及数据表：** application（核心）

**实现流程：**

1. **流程配置**（简化版）
   - **方案A：** 写在配置文件或枚举类
   ```java
   public enum ApprovalFlowConfig {
       PROJECT_UP(2, "项目上架需机构+专家审批"),
       EXCHANGE(1, "积分兑换仅需机构审批"),
       CERT_APPLY(2, "认证申请需机构+专家审批");
   }
   ```
   - **方案B：** 新建流程配置表（可选）
   ```sql
   CREATE TABLE approval_config (
       biz_type VARCHAR(30),
       approval_levels INT,
       level1_role VARCHAR(20),
       level2_role VARCHAR(20)
   );
   ```

2. **申请单创建逻辑**
   - 根据 biz_type 获取审批级数配置
   - **1级审批：** current_status 初始化为 1（待机构审）
   - **2级审批：** current_status 初始化为 1（待机构审，后续转2）

3. **审批状态机流转**
   - **状态定义：**
     - 0：草稿
     - 1：待机构审批
     - 2：待专家审批
     - 3：审批通过
     - 4：审批驳回
   
   - **流转规则：**
     - 0 → 1：提交申请
     - 1 → 2：机构通过（2级审批）
     - 1 → 3：机构通过（1级审批）
     - 1 → 4：机构驳回
     - 2 → 3：专家通过
     - 2 → 4：专家驳回

4. **待办列表展示**
   - **机构管理员待办：**
     - 查询 application 表（current_status=1 AND org_id=当前机构）
   - **专家待办：**
     - 查询 application 表（current_status=2 AND expert_id=当前专家）

5. **审批操作**
   - 点击"通过"：按状态机更新 current_status
   - 点击"驳回"：更新 current_status=4，填写 reject_reason
   - 审批通过后触发对应业务逻辑（如项目上架、积分扣除等）

```java
// 审批通过逻辑

public void approve(Long applicationId, Long approverId) {

        app.setCurrentStatus(3);
        executeBizLogic(app);
    }
    
    applicationMapper.updateById(app);
}
```

### 功能5：平台活动管理

**系统描述：** 发起限时活动（如"国庆学习积分1.5倍"），活动期间完成项目奖励加成。

**涉及数据表：** campaign、project、transaction_log、credit_rule、sys_user

**实现流程：**

1. **活动列表展示**
   - 查询 campaign 表所有记录
   - 前端展示：活动标题、积分倍率、适用项目、开始/结束时间、状态

2. **新增活动**
   - 管理员填写：title、multiplier、project_ids、start_time、end_time
   - 计算初始状态：
     - 当前时间 < start_time → status=0（未开始）
     - start_time <= 当前时间 <= end_time → status=1（进行中）
   - 插入 campaign 表

3. **编辑活动**
   - 根据 id 查询现有活动
   - 管理员修改相关字段
   - 更新 campaign 表

4. **活动状态自动更新**（定时任务）
   - 每5分钟或每次查询时判断：
     - 查询 status=0 且 start_time <= 当前时间 → 更新 status=1
     - 查询 status=1 且 end_time < 当前时间 → 更新 status=2
   - **定时任务实现：**
   ```java
   @Scheduled(cron = "0 */5 * * * ?") // 每5分钟执行
   public void updateCampaignStatus() {
       // 更新未开始→进行中
       campaignMapper.updateStatus(0, 1, startTimeCondition);
       // 更新进行中→已结束
       campaignMapper.updateStatus(1, 2, endTimeCondition);
   }
   ```

5. **积分发放加成逻辑**（核心业务）
   - 学生完成项目，触发积分发放时：
   - **查询当前活动：**
   ```java
   List<Campaign> activeCampaigns = campaignMapper.selectList(
       new LambdaQueryWrapper<Campaign>()
           .eq(Campaign::getStatus, 1)
           .le(Campaign::getStartTime, now)
           .ge(Campaign::getEndTime, now)
   );
   ```
   - **计算加成积分：**
     - 获取基础积分：credit_rule.credit_value
     - 判断项目是否在 project_ids 中（或 project_ids 为空表示全平台）
     - 实发积分 = 基础积分 × multiplier
   - **写入流水：**
     - transaction_log.description 添加备注："活动加成（1.5倍）"

**关键代码逻辑：**
```java
// 积分发放（含活动加成）
@Transactional
public void rewardWithCampaign(Long userId, Long projectId, String eventCode) {
    // 1. 获取基础积分
    CreditRule rule = creditRuleMapper.selectByEventCode(eventCode);
    BigDecimal baseCredit = rule.getCreditValue();
    
    // 2. 查询有效活动
    List<Campaign> campaigns = campaignMapper.selectActiveCampaigns(projectId);
    
    // 3. 计算加成
    BigDecimal finalCredit = baseCredit;
    String remark = rule.getEventName();
    
    if (!campaigns.isEmpty()) {
        Campaign campaign = campaigns.get(0); // 取最高倍率
        finalCredit = baseCredit.multiply(campaign.getMultiplier());
        remark += "（活动加成" + campaign.getMultiplier() + "倍）";
    }
    
    // 4. 更新用户积分
    SysUser user = sysUserMapper.selectById(userId);
    user.setBalance(user.getBalance() + finalCredit.intValue());
    sysUserMapper.updateById(user);
    
    // 5. 写入流水
    TransactionLog log = new TransactionLog();
    log.setUserId(userId);
    log.setAmount(finalCredit.intValue());
    log.setBalanceAfter(user.getBalance());
    log.setBizType("REWARD");
    log.setDescription(remark);
    transactionLogMapper.insert(log);
}
```

### 功能7：项目管理

**系统描述：** 管理平台上开设的课程/课题，相当于"积分商城的商品货架"。

**涉及数据表：** project、application、sys_user、transaction_log、credit_rule、campaign、organization

**实现流程：**

1. **项目列表展示**
   - 查询 project 表（status=1 已上架）
   - 前端展示：项目名称、机构、专家、奖励积分、报名费用、状态
   - 学生端：仅展示已上架项目
   - 机构端：展示本机构的所有项目（含待审核）

2. **机构提交项目**
   - 机构管理员填写：name、description、credit_reward、credit_price、expert_id
   - 插入 project 表（status=0 待审核）
   - **同时创建审批单：**
     ```java

     app.setBizType("PROJECT_UP");
     app.setBizKey(projectId);
     app.setApplicantId(orgAdminId);
     app.setOrgId(orgId);
     app.setCurrentStatus(1); // 待机构审批（或直接待专家审）

     ```

3. **项目审批流程**

     - 查询 application 表（biz_type='PROJECT_UP', current_status=1）

     - 查询 project 获取 credit_price
     - 查询 sys_user 获取学生 balance
     - 校验：balance >= credit_price（积分足够）
   - **报名操作：**
     - 扣减积分：sys_user.balance -= credit_price
     - 写入流水：transaction_log（amount=-credit_price, biz_type='EXCHANGE', biz_id=projectId）
     - 创建学习记录（建议新建 user_project 中间表）

5. **学生完成项目**
   - **触发积分发放：**
     - 获取 credit_rule（event_code='PROJECT_COMPLETE'）
     - 查询 campaign 判断是否有活动加成
     - 计算实发积分 = credit_reward × multiplier
     - 增加积分：sys_user.balance += 实发积分
     - 写入流水：transaction_log（amount=+积分, biz_type='REWARD', biz_id=projectId）

6. **项目下架**
   - 管理员操作：更新 project.status=2（已下架）
   - 下架后学生端不再显示
   - 已报名学生可继续完成

```java
@Transactional
public void enrollProject(Long userId, Long projectId) {

    SysUser user = sysUserMapper.selectById(userId);

    log.setBizId(projectId.toString());

    transactionLogMapper.insert(log);
    
    // 创建学习记录
    UserProject userProject = new UserProject();
    userProject.setUserId(userId);
    userProject.setProjectId(projectId);
    userProject.setStatus(0); // 进行中
    userProjectMapper.insert(userProject);
}
```

```java
    orgAdmin.setRealName(org.getContactPerson());
    orgAdmin.setPhone(org.getContactPhone());
    orgAdmin.setRole("org_admin");
    orgAdmin.setOrgId(orgId);
    orgAdmin.setBalance(0);
    orgAdmin.setStatus(1);
    sysUserMapper.insert(orgAdmin);
}

// 禁用机构及联动冻结用户
@Transactional
public void disableOrganization(Long orgId) {
    // 禁用机构
    organizationMapper.updateStatus(orgId, 2);
    
    // 批量冻结该机构所有用户
    sysUserMapper.update(
        new LambdaUpdateWrapper<SysUser>()
            .eq(SysUser::getOrgId, orgId)
            .set(SysUser::getStatus, 0)
    );
}
```

## 三、核心业务流程总结

### 积分发放核心流程（所有涉及积分变动的功能复用）

```
1. 查询积分规则（credit_rule）
2. 查询当前活动（campaign）判断加成
3. 计算实发积分 = 基础积分 × 倍率
4. 更新用户余额（sys_user.balance）【需乐观锁防并发】
5. 写入交易流水（transaction_log）【只增不改，防篡改】
6. 返回成功提示
```

### 申请审批核心流程（项目上架、积分兑换、认证申请复用）

```
1. 创建申请单（application）
   - 根据biz_type初始化current_status
2. 审批人查询待办（按current_status和角色过滤）
3. 审批操作：
   - 通过：按状态机更新current_status
   - 驳回：current_status=4，填写reject_reason
4. 审批通过后执行业务逻辑：
   - 项目上架：更新project.status=1
   - 积分兑换：扣减积分+扣减库存
   - 认证申请：生成证书
```

### 权限控制核心逻辑

```
1. 用户登录：查询sys_user获取role和org_id
2. 角色权限：
   - admin：全平台权限（或按admin_role_menu过滤）
   - org_admin：仅本机构数据（org_id过滤）
   - expert：仅自己负责的项目（expert_id过滤）
   - student：仅自己的数据（user_id过滤）
3. 数据过滤：所有查询自动添加权限条件
```

## 四、技术要点提示

1. **事务控制：** 所有涉及积分变动、库存扣减的操作必须加 @Transactional

2. **乐观锁：** sys_user.balance 更新需加版本号字段防并发冲突

3. **流水账本：** transaction_log 只增不改，balance_after 记录变动后余额快照

4. **数据驱动规则：** 积分值、认证标准、兑换规则全部存表，不写死在代码

5. **审批状态机：** application.current_status 严格按状态机流转，不可跳跃

6. **定时任务：** 活动状态更新建议用 Spring @Scheduled 定时执行

7. **权限过滤：** 所有查询接口需根据角色自动添加 WHERE 条件

8. **日志记录：** 关键操作（审批通过、积分变动）建议记录操作日志
